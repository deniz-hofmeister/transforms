## [loud-in-ordinary-use] Self-lookup and 'latest' on a not-yet-populated or single-frame registry turns from identity into a permanent error; the dependents study records a downstream test asserting the identity, and DESIGN.md does not cite it
RULINGS: R2 (with M2, R3/SelfEdge)
SCENARIO: Empty registry (startup before the first /tf message, or a system with one frame and no TF at all): `lookup("map","map",t)`, `latest_common_time("map","map")`, `lookup_across("map",t1,"map",t2,"map")`. 2.4 returns identity / `Static` / identity; v3 returns `UnknownFrame{"map"}` for all three. The M2 recipe for 'latest' (`latest_common_time` then `lookup`) therefore fails at its first call. A lone frame can never be made known: the only way to get a slot is a stored edge, and `insert` of (x,x) is `SelfEdge`, so a one-frame application must invent a dummy edge. Wait wrappers are error-blind (pelorus polls 10 ms for 5 s on any `Err`), so the previously instant identity becomes a 5 s timeout with no cause.
EVIDENCE: Probe on 2.4 (scratchpad/rulings-r2): `1 empty self: Ok(0,0,0)`, `1 empty lct self: Ok(Static)`, `1 empty across all-equal: Ok(0,0,0)`. analysis/dependents/dimos.md:237: "dimos's own test asserts that `get_latest(\"map\",\"map\")` returns identity (`tf.rs:444-455`)"; dimos.md:513 and analysis/dependents/README.md:559-562 list `UnknownFrame` for equal unregistered names under 'Do not'. DESIGN.md mentions dimos only at line 353 (time type); evidence/map-dependents.md has no row for this. map-dependents.md:128 for the error-blind wait loops. DESIGN.md:453-456 (rule), :473-475 (`SelfEdge`). I did not read dimos's tf.rs itself, only the study's citation, and did not check whether that test runs on an empty registry.
FIX: Keep the ruling; add to DESIGN.md's declared consequences and the migration notes: the dimos `get_latest("map","map")` test breaks, a single-frame registry cannot answer a self-lookup, and adapters that want the old behaviour short-circuit `target == source` themselves.

## [contradiction] The contract's claim that a compose-derived self-named transform is "the identity only up to rounding" is false; ordinary derived self-named values are far from identity

SCENARIO: Pose-error computation at one stamp: est = new("map","base",(1.0,2.0,3.0), yaw 90deg, At(5)); truth = new("map","base",(1.1,2.0,3.0), same rotation, At(5)); est.inverse()?.compose(&truth)? is a legal base<-base Transform with translation (0, -0.1, 0).
